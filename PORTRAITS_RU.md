# Портреты BytePlus: подключение и использование

Версия 0.7.5 добавляет официальный процесс: проверка человека или группа AI-персонажа → `CreateAsset` → статус `Active` → `asset://ID` в генерации. Нажми **Портрет** у изображения в Media или в панели Video. Кнопка **Использовать фото напрямую** возвращает обычный режим референса; он по-прежнему может быть отклонён проверкой BytePlus.

## Что разрешает BytePlus

- Библиотека реальных людей доступна приглашённым аккаунтам с соответствующими Advanced Creation Rights. Человек сам проходит проверку по ссылке BytePlus и даёт разрешение на использование своего образа. Код не включает эти права в аккаунте.
- Каждому реальному человеку соответствует собственная группа. После проверки следующие фото того же человека можно добавлять в неё без повторной проверки человека. Новое фото всё равно проходит регистрацию и обработку как отдельный asset.
- В реальной группе принимается одно лицо на изображении. Фото с несколькими людьми не подходит для этой библиотеки. Сам факт регистрации не гарантирует, что любые материалы или генерации пройдут проверки провайдера.
- Для вымышленных AI-персонажей используется отдельная группа `AIGC`; до первого создания нужно принять разрешение библиотеки в консоли BytePlus. Реальные люди не становятся AI-персонажами от выбора этой кнопки.
- 20–30 фото одного проверенного человека можно последовательно зарегистрировать в одной группе, если это допускают права и квоты аккаунта. Для 20–30 разных людей нужны отдельные проверки и группы.

Официальная документация:

## Настройка Worker

Assets API требует **Access Key ID / Secret Access Key (AK/SK)**. Обычный ARK API Key используется отдельно для генераций. В BytePlus выдай серверному AK/SK права ModelArk на нужный Project; оба вида ключей должны обращаться к одному аккаунту и проекту. Не вставляй AK/SK в HTML, Firebase или GitHub.

В терминале из папки проекта:

```bash
cd cloudflare-worker
npm install
npx wrangler secret put ARK_API_KEY
npx wrangler secret put BYTEPLUS_ACCESS_KEY_ID
npx wrangler secret put BYTEPLUS_SECRET_ACCESS_KEY
```

`ARK_API_KEY` уже может быть настроен. Рекомендуется также отдельный постоянный случайный `TASK_TOKEN_SECRET` через `npx wrangler secret put TASK_TOKEN_SECRET`. Если его нет, подтверждения подписываются ARK ключом; изменение подписывающего секрета делает старые подтверждения недействительными.

В существующем блоке `[vars]` файла `wrangler.toml` добавь:

```toml
ALLOWED_ORIGIN = "https://voloshanenkodanil3457-cyber.github.io"
BYTEPLUS_PROJECT_NAME = "default"
PORTRAIT_CALLBACK_URL = "https://voloshanenkodanil3457-cyber.github.io/aiagr/portrait-callback.html"
```

Если используешь другой Project или домен, замени значения. Страница `portrait-callback.html` должна быть опубликована на GitHub Pages. Параметры обратной ссылки не дают права на группу: результат всегда проверяется Worker через `GetVisualValidateResult`.

## Локальные фото: временный HTTPS-доступ

`CreateAsset` требует доступный провайдеру HTTPS URL и не принимает локальный `blob:` или Base64. Для фото с компьютера:

1. Создай приватный Cloudflare R2 bucket, например `magic-portrait-staging`. Публичный доступ к bucket не нужен.
2. В его Lifecycle Rules включи удаление объектов с префиксом `portrait-staging/` через один день. Это удалит файлы, оставшиеся после закрытия страницы, ошибки или потери ответа.
3. В конце `wrangler.toml` раскомментируй или добавь привязку:

```toml
[[r2_buckets]]
binding = "PORTRAIT_FILES"
bucket_name = "magic-portrait-staging"
```

Worker выдаёт временную подписанную ссылку на конкретное фото на 24 часа. При получении `Active` или `Failed` временный объект удаляется. Сам зарегистрированный asset остаётся в BytePlus; ненужные assets и группы удаляй через My assets. Локально поддерживаются JPG, PNG и WebP меньше 30 МБ; размеры, лица и остальные требования проверяет BytePlus.

Без R2 можно добавить изображение кнопкой **По ссылке**, используя HTTPS URL, доступный BytePlus без авторизации. Если содержание изображения по этому URL меняется, добавь новый URL или локальный файл: повторное использование привязано к URL либо хешу локального файла.

Firebase остаётся на Spark и хранит метаданные; изображения и видео в Firebase Storage не загружаются. Бесплатность всего процесса не гарантируется: права библиотеки, генерации, хранение BytePlus и использование R2 определяются условиями и квотами этих сервисов.

## Публикация и работа с фото

Сначала собери и опубликуй страницы, затем обнови Worker:

```bash
# Из корня проекта
python source/build.py
cd cloudflare-worker
npm run deploy
```

В приложении подключи этот Worker URL в **My settings**. Генерации тогда используют серверный ARK ключ Worker. Режим Direct продолжает работать для обычных фото, но процесс Assets требует Worker.

1. Добавь фото и нажми **Портрет**.
2. Для AI-персонажа введи имя и нажми **Новый AI-персонаж**. Для реального человека выбери **Проверить реального человека**, пройди проверку в открывшейся вкладке, вернись и нажми **Проверить результат**. Сессия проверки действует 30 минут.
3. Выбери созданную группу и нажми **Привязать группу к фото**. Следующие фото этого персонажа привязывай к той же группе.
4. Кнопка **Зарегистрировать / проверить фото** заранее проверяет готовность. Можно сразу нажать Generate: приложение выполнит регистрацию и дождётся `Active` перед отправкой задачи.
5. Повторная генерация с тем же файлом и группой использует сохранённый Asset ID. При долгой обработке нажми проверку позже: файл повторно не регистрируется.

Группы и подписанные подтверждения привязаны к Firebase UID, аккаунту/проекту BytePlus и адресам сайта/Worker. Подтверждения хранятся только в этом браузере, не в схеме Firestore, и действуют 60 дней. Обычный пользователь не может подключить чужую группу из общей консоли. Суперадмин может подключить существующую группу через её ID в окне «Портрет». В другом браузере потребуется подключить группу заново; для обычного пользователя это доступный ему процесс проверки/создания группы. Не очищай данные браузера, если нужны эти сохранённые привязки.

Если ответ `CreateAsset` потерян, автоматический повтор отключён, чтобы не создавать дубликаты. Открой **BytePlus → My assets**, найди зарегистрированное фото и введи его ID в поле **Asset ID именно этого фото из выбранной группы**. Если фото отсутствует, проверь причину в BytePlus перед повторной загрузкой. Ошибка `Failed` не приводит к платной отправке генерации; её причина выводится в интерфейсе.

Если BytePlus отвечает отказом в доступе или лицо не проходит проверку, это ограничение провайдера. В коде нет отключения модерации или автоматической подмены реального лица.
