# Ссылки на референсы в промптах

SM video, поле промпта в ноде Canvas и плавающая панель Canvas подсвечивают @image1, @video1 и варианты @image_1 / @video_1. SM также поддерживает @audio1. Ссылки нумеруются отдельно по типу в том же порядке, в котором медиа попадают в запрос генерации. Canvas учитывает входящие Media и исключённые референсы; BytePlus в SM не имеет подключённых медиа.

При наведении отображаются имя и превью именно соответствующего файла. Видео запускается без звука. Отключённый или отсутствующий номер помечается янтарным и сообщает, что референс не подключён. Удаление/подключение файлов обновляет и ноду, и composer. Неизвестные номера не подменяются ближайшим референсом.

Редактор остаётся обычным textarea: текст запроса, выделение, каретка, копирование, Undo и события ввода сохраняются. Отдельный зеркальный слой рисует подсветку с теми же размерами, шрифтом, переносами и прокруткой. Он не перехватывает мышь; попадание на токен определяется по его экранным прямоугольникам, включая масштаб Canvas. Превью создаётся DOM-элементами без вставки промпта через HTML. Нет запросов к ИИ или видео API при наведении.

Проверено: отдельная нумерация изображений/видео, оба написания токенов, отсутствующие номера, SM-превью второго фото и видео, Canvas-нода и composer, обновление ссылок после исключения фото. Browser QA использует тестовые медиа и mock Firebase; платных генераций нет.

Одновременно исправлены блокирующий запуск SM get отсутствующего private Space, локальное добавление/восстановление фото и меню параметров (один уровень выбора, синхронное закрытие, число 4 секунды, меню выше кнопки Generate). Регрессионный тест воспроизводит отказ чтения отсутствующего Space и сохранение конкурентного черновика при merge. Firestore rules не изменялись; Java для запуска настоящего эмулятора в этой среде недоступна.
