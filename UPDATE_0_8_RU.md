## Обновить сайт

Прямое создание ветки через подключение GitHub завершилось ответом `403 — Resource not accessible by integration`. В удалённом репозитории изменений этим подключением не опубликовано. В архиве находятся проверенные изменения для обычного пуша из VS Code.

Сделай копию своей папки проекта. Скопируй содержимое `aiagr` из архива в папку открытого репозитория в VS Code, сохранив её существующую папку `.git`. В архиве есть все исходники, готовые HTML и тесты; зависимости `node_modules` не включены.

В терминале VS Code из папки репозитория:

```powershell
git status
git add .
git commit -m "Add OpenRouter, camera movements and video previews"
git push origin main
```

Если GitHub Pages уже публикует main / root, эти HTML появятся после успешного развёртывания Pages. Затем обнови страницу без кеша (`Ctrl+F5`). Worker обновляется отдельно, даже если сайт уже появился.

## Подключить OpenRouter

1. My settings → OpenRouter → вставь ключ → **Подключить**. Если другой провайдер активен, сохранение нового ключа его не переключает.
2. **Проверить** проверяет ключ и наличие Seedance 2.5 в видеокаталоге. Платный запрос генерации не отправляется. Проверка не гарантирует успешную генерацию: баланс, доступ к модели и проверка содержимого действуют на стороне OpenRouter.
3. **Включить** выбирает OpenRouter для новых задач Seedance 2.5 и отключает BytePlus. Обратное переключение действует так же.
4. **Отключить** сохраняет ключ. «Удалить подключение» удаляет его из текущего браузера.

Используется модель `bytedance/seedance-2.5` и отдельный Video API OpenRouter; запросы не отправляются в chat/completions. Параметры проверяются по актуальному видеокаталогу до отправки задачи. На момент проверки каталог указывает 480p/720p, 4–30 секунд и шесть форматов; 1080p недоступно. После проверки ключа неподдерживаемые настройки отключены в панели. Старые ноды с неподдерживаемыми параметрами покажут ошибку до платного запроса.

Локальное фото передаётся как Base64. Локальное видео требует доступной HTTPS-ссылки, как и раньше. BytePlus `asset://` не переносится в OpenRouter: используется исходное фото, если оно сохранилось в этом браузере. Все обычные правила проверки содержимого выбранного провайдера действуют.

## Смотреть ролики команды через Worker

Direct API подходит для личного тестирования: владелец получает видео своим ключом. Суперадмин видит карточки и отчёт всех участников, но воспроизведение чужого Direct-ролика требует доступа к исходному ключу; сайт его не передаёт. Для общего просмотра новых роликов подключи Worker у всех участников до генерации. Уже созданные Direct-ролики автоматически не переводятся в Worker.

Открой `cloudflare-worker` в терминале:

```powershell
cd cloudflare-worker
npm install
```

В `wrangler.toml` уже задан проект `aiagr-80390`. Укажи origin сайта (без `/aiagr/`):

```toml
[vars]
FIREBASE_PROJECT_ID = "aiagr-80390"
ALLOWED_ORIGIN = "https://voloshanenkodanil3457-cyber.github.io"
```

Если уже используешь этот Worker, сохрани его имя и существующие secrets. Если ранее подтверждения подписывались `ARK_API_KEY`, при добавлении отдельного `TASK_TOKEN_SECRET` используй то же значение для совместимости со старыми задачами. Если подписывающий секрет уже существует, повторно задавать его не нужно.

Для нового Worker без ARK-ключа:

```powershell
npx wrangler secret put TASK_TOKEN_SECRET
```

Введи длинную случайную строку в запросе терминала. Этот секрет нужен для подписи и шифрования подтверждений задач; API-ключ OpenRouter им не является. Затем:

```powershell
npm run deploy
```

В My settings → OpenRouter вставь личный OpenRouter key и URL опубликованного Worker → **Подключить → Проверить → Включить**. У суперадмина и пользователей должен быть один и тот же Worker URL. Нажатие «Проверить» также обновляет подписанную сессию с текущей ролью.

Worker получает видео от OpenRouter потоком, включая Range для перемотки. Создавать R2 или Firebase Storage для этих результатов не нужно. Видео и фото не копируются в Firestore; там остаются параметры, стоимость, ссылка и зашифрованное подтверждение. Свойства ключа ограничивают сам OpenRouter; срок хранения результата определяет провайдер. Срок подтверждения задачи — 60 дней, ссылки просмотра — 30 минут. Не меняй подписывающий секрет при обычном обновлении Worker: старые подтверждения после смены перестанут работать.

## Camera movement

`modifiers.html` теперь содержит Camera movement. Все 46 предоставленных ссылок и полных промптов находятся в `source/camera-movements.js`. Это статический каталог: чтений Firestore для карточек нет. Видео загружаются с исходного сайта по мере появления карточек на экране; скрытые видео приостанавливаются. Если исходный сайт уберёт видео, его ссылка перестанет работать.

- Поиск и семь категорий фильтруют примеры.
- **Copy prompt** копирует полный текст.
- **Turn into video** предлагает только твои Spaces и создаёт отдельную ноду Camera.
- Соедини выход Camera с входом Video generation. Полный текст камеры добавляется в итоговый промпт после основного описания. Можно выключить подключённый пресет или изменить порядок пресетов.
- Перезагрузка не создаёт второй экземпляр той же вставленной ноды.

Редактирование нод, настроек, связей и загрузка локального фото остаются локальными. Результат генерации и схема отправляются в БД при завершении; очередь схемы при F5 отправляется на следующей загрузке приложения. Закрытие вкладки само по себе не гарантирует сетевую отправку.

## Предпросмотр и права

В Assets нажми карточку или «Предпросмотр»: видео откроется поверх приложения, фон размыт, пропорции берутся из самого файла. «Промпт» раскрывает весь текст с прокруткой, нажатие на текст копирует его. «Описание» показывает автора, дату, модель, провайдера, формат, разрешение, длительность и аудио. Скачать можно отдельной кнопкой.

В Output нажми ↗ или дважды нажми видео: такой же слой, только видео и скачивание. Обычный браузерный fullscreen заменён этим просмотром. Escape закрывает просмотр; ноды при этом не удаляются.

Суперадмин читает все записи генераций в Assets. Пользователь запрашивает только свои. Spaces и исходные медиа остаются строго личными, включая для суперадмина. Правила `firestore.rules` в этом обновлении не изменены: проверены существующие правила версии 0.7.5. Если в Firebase до сих пор опубликованы старые правила с доступом администратора к чужим Spaces, нужно отдельно опубликовать файл правил из проекта.
