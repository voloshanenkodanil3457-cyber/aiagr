# Elements / Avatars — подключение

Структура готова. Демонстрационные изображения не публикуются. Пока Supabase не подключён, папки GEO пустые.

1. Создай Supabase project на Free. Не переходи на Pro.
2. Authentication → Third-party Auth → Firebase: добавь Project ID `aiagr-80390`.
3. SQL Editor: выполни `supabase/avatars.sql` один раз. Вставь свой Firebase UID в указанную строку INSERT avatar_admins и выполни её. UID — не пароль. Роль SuperAdmin в Magic сама по себе не даёт доступ к Supabase: серверная таблица разрешённых администраторов обязательна.
4. В SM video → Elements → Подключение Supabase введи Project URL и `sb_publishable_…` из Connect / API Keys. Secret/service_role не используй. Нажми «Сохранить и проверить».
5. Для общего подключения всем пользователям впиши эти два публичных значения в `window.MAGIC_AVATAR_STORAGE={url:'https://PROJECT.supabase.co',key:'sb_publishable_…'}` в source/firebase-config.js и пересобери сайт. Настройка через панель пока сохраняется только в этом браузере.
6. SuperAdmin увидит форму загрузки: имя, GEO, пол, возраст, описание, готовое фото. Изображение сохраняется в Storage, карточка — в Supabase. Лимит одного фото 8 МБ. Если возраст неизвестен — оставь пустым; национальность по внешности не определяем, GEO означает рынок/сценарий.
7. Выбери карточку — она становится обычным референсом @image1 в SM video. Для BytePlus text-only нужно сначала выбрать модель с поддержкой фото.

Проверка после подключения: администратор загружает фото; обычный пользователь видит его, но не может загрузить/изменить через API; после обновления и на втором устройстве карточка остаётся. Не запускай генерацию для этой проверки.

Bucket публичный: любой, у кого есть ссылка, может увидеть фото. Библиотека подходит для изображений, предназначенных для общего использования. Каталог доступен только пользователям нашего Firebase-проекта. RLS проверяет issuer/audience/UID, не доверяет роли из браузера, admin allowlist недоступен для записи клиенту. Для текущего Firebase JWT без role используются строго ограниченные политики anon; запрос без валидного Firebase JWT не получает доступ к каталогу и загрузке.

Шаблон единого листа персонажа сохранён без изменений в source/avatar-sheet-prompt.txt. Генерация не запускается кнопкой загрузки. Она не реализует обучение персонажа: это передача выбранного изображения как референса.

Следующий этап: генерация готовых листов после выбора доступной image-модели, проверка результата, затем загрузка. «GPT image2.5» пока не привязан к API и не заявлен как работающая модель. В примерах из PDF фотографии являются визуальными аналогами; они не загружены в общую библиотеку. Импорт папок/массовая генерация — отдельный следующий этап, сейчас реализована структура и одиночная загрузка.

Бесплатные квоты Supabase ограничены; проект Free может приостанавливаться при неактивности. Состояние подключения и фактический upload ещё не проверены: проект не создан.
