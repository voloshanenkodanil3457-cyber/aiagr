# SM video / Simple Mode

У каждого аккаунта закреплено личное пространство `simple_<uid>`. Список Canvas всегда показывает его первым и направляет на `sm-video.html`. У карточки нет переименования/дублирования/удаления; соответствующие операции Studio также запрещены. Документ создаётся идемпотентной транзакцией при первом открытии. При удалении через внешнюю консоль он будет восстановлен; это системная функция приложения, а не новые права Firestore. Старые private-only правила Spaces сохраняются без изменений.

Черновик и метаданные референсов сохраняются в собственном `canvasState` этого пространства, с резервной локальной копией по UID. Файлы хранятся локально и по доступным провайдеру HTTPS-ссылкам; локальные blob URL не отправляются в базу. Удалённая доступность медиа зависит от срока жизни ссылок у провайдера/временного загрузчика. История генераций использует обычные videos, личный spaceId, Assets и общий Cost.

## Модели
- Higgsfield Seedance 2.5: 4–30 сек., 480/720/1080p, 6 форматов, звук, High/Standard, фото/видео/аудио.
- Higgsfield Seedance 2.0: 4–15 сек., 480/720/1080p, звук, фото/видео/аудио; битрейт не заявлен API и скрыт. До 9 изображений, 3 видео, 3 аудио. Только аудио без фото/видео не запускается.
- BytePlus Seedance 2.5: в Simple Mode только текст; сохранённые референсы скрыты и исключаются из запроса. Режим использует подключение BytePlus независимо от глобального выбора провайдера; глобальную настройку не меняет.
- Higgsfield Kling 4.0: `kling-video/v4.0/text-to-video` без референсов и `.../reference-to-video` с фото/видео. До 10 фото / 5 видео. Только 720/1080p и 21:9/16:9/9:16/1:1; неподдержанные звук/битрейт/аудиореференсы не отправляются. API допускает 3–30 секунд; интерфейс пока использует 4–30, совместимые с текущим учётом/Firestore videos. Seedance не подставляется вместо Kling.

По умолчанию Seedance 2.5, 5 секунд, 9:16, 480p, звук включён, High. Все Higgsfield-запуски требуют отдельного подтверждения. Улучшение промпта использует существующий бесплатный Worker AI, не запускает видео и позволяет отменить правку. Kling использует алиасы `@image_1`/`@video_1`, Seedance — `@image1`/`@video1`.

Для сохранения выбранного формата single-image Seedance в SM направляется в reference-to-video. Payload не содержит пустых reference-массивов и неподдержанного output_format (live schema additionalProperties=false); для других страниц сохраняется существующий выбор image-to-video/video-edit.

## Учёт и проверки
Сохраняются requestId, modelEndpoint, модель, параметры, audio/bitrate и известная длительность входных видео. Сначала используется API-оценка; без неё Seedance имеет публичную оценку, Kling остаётся без цены до получения данных или ручной сверки Billing. Неизвестные суммы не считаются нулём.

Платных тестовых генераций при разработке не выполнялось. UI прошёл проверку на заглушке API: отмена до submit, Kling endpoint, получение завершённого результата, стоимость в общем Cost, восстановление черновика, постоянное пространство и удаление референса. Unit/integration tests используют тестовые токены и ответы.

Проверенные официальные схемы 24.10.2026:

- https://open.higgsfield.ai/models/kling-video/v4.0/reference-to-video/api-reference
- https://open.higgsfield.ai/models/bytedance/seedance-2.5/reference-to-video/api-reference
- https://open.higgsfield.ai/models/bytedance/seedance-2.0/reference-to-video/api-reference

Подключение требует публикации обновлённого magic-higgsfield Worker с прежними HF_CREDENTIALS и AI bindings. Ключи не читаются и в браузер не передаются. Успешная платная генерация Kling на реальном аккаунте не подтверждалась.
