# Magic · обновление 0.8.1

Новые правки поверх полного архива 0.8.0: видеопример в ноде Camera movement, удаление результатов и ошибок из базы суперадмином с защитой от повторной синхронизации. Сначала прочитай [UPDATE_0_8_1_RU.md](UPDATE_0_8_1_RU.md): перед обновлением сайта нужно опубликовать новые правила Firestore.

Обновление подготовлено на основе GitHub `voloshanenkodanil3457-cyber/aiagr`, main `6c787327bb54c194a08ed560a9f69a20cedfb8dc` (0.7.5). Это готовые статические HTML-страницы и их исходники. Существующий Firebase project ID сохранён. Эта версия использует Spark: Firebase Storage не подключается; в Firestore хранятся только данные и ссылки. Публикация сайта и Worker — отдельный шаг. Инструкция к новому обновлению: [UPDATE_0_8_RU.md](UPDATE_0_8_RU.md).

## Что изменено

- **OpenRouter (0.8.0)**: отдельное подключение и бесплатная проверка ключа через `/api/v1/key`, проверка видеокаталога, запуск Seedance 2.5 через `/api/v1/videos`. Включение OpenRouter отключает BytePlus для новых задач, и наоборот; ключи сохраняются. Существующая задача продолжает использовать свой провайдер. Это не делает сами генерации бесплатными.
- **Camera movement** заменяет Modifiers по прежнему адресу `modifiers.html`: все 46 предоставленных видео, 7 категорий, поиск, Copy prompt и Turn into video с выбором собственного Space. Отдельная нода камеры подключается к Video generation; передаётся весь её промпт.
- **Предпросмотр** открывает модальное окно с размытым фоном и исходными пропорциями видео. Assets: полный прокручиваемый промпт с копированием, сведения об авторе и параметрах. Output: видео и скачивание.
- **Командный просмотр OpenRouter** работает через обновлённый Worker. Direct API позволяет владельцу смотреть свои ролики; суперадмин видит карточки и отчёт, но чужой ключ ему не передаётся. Для полного просмотра команды все участники указывают один доверенный Worker URL.
- Автоматическая проверка портретов из промежуточной 0.7.6 отложена. Сохранён прежний ручной процесс 0.7.5.

- **Портреты (0.7.5)**: официальная проверка реального человека или группа AI-персонажа, регистрация фото и `asset://ID` после `Active`. Нужны права библиотеки BytePlus, AK/SK в Worker и HTTPS-доступ к фото. Настройка: [PORTRAITS_RU.md](PORTRAITS_RU.md).

- Две роли: `superuser` и `user`. Страница **Users** доступна суперадмину: создание аккаунтов и смена ролей. Создание аккаунта не выводит администратора из его сессии. Свою роль понизить нельзя.
- Самостоятельная регистрация удалена. Профиль участника создаёт суперадмин; одного Firebase Auth токена недостаточно для доступа к базе и новому Worker.
- **Spaces строго личные**, включая для суперадмина. Запросы всегда содержат `ownerUid == текущий UID`. Вкладка общих Spaces убрана.
- **Assets / Dashboard**: суперадмин видит генерации и отчёт всей команды, пользователь — только свои. Чужие Spaces нельзя открыть из карточки результата. Исходные медиа приватны даже от суперадмина.
- В отчёте есть ник, количество, успехи, ошибки, XP и сумма стоимости, которую вернул API. Если API не сообщил цену, показано отсутствие данных; цена не выдумывается. Отчёт не является сверкой со счётом BytePlus.
- Удаление карточки заменено архивированием: история, рейтинг и доступ суперадмина к результату сохраняются.
- **Media**, **Preset**, **Video**, **Output** разделены. Пресет показывает заголовок и сокращённый текст; в запрос уходит весь текст.
- Нода Video содержит промпт. По нажатию открывается панель под нодой: референсы, модель, Omni Reference, настройки, x1/x2/x4 и Generate. Третья панель содержит 480p/720p/1080p, 4–30 секунд, формат и аудио.
- Потяни `+` в пустое место: справа от Video — Output, слева — Media / Preset. Между существующими портами сохраняется обычное соединение.
- Генерация использует уже подключённые Output. Дополнительные Output и связи создаются только если их не хватает для выбранного количества.
- **Winners**: рейтинг XP, рейтинг ошибок и интерактивный калькулятор. Общая коллекция содержит только ники и итоги, без промптов, цен и видео. Суперадмин может пересчитать старую историю кнопкой «Пересчитать рейтинг».
- **Saved Values** удалена из сборки и навигации.

## Как сохраняются Spaces

| Действие | Сохранение / сеть |
| --- | --- |
| Ноды, связи, промпты, параметры, перемещение | Локальный снимок в браузере; Firestore не вызывается |
| Добавление файла | IndexedDB на компьютере; Firestore не вызывается |
| Начало генерации | Запрос выбранному API; локальные изображения передаются в Base64, видео по HTTPS-ссылке; без Firebase Storage и записи в Firestore |
| Проверка статуса | Только API; состояние задачи и её ID сохраняются локально |
| Готовый результат или подтверждённая ошибка API | Результат и рейтинг сохраняются атомарно; отдельным контрольным сохранением отправляется схема |
| F5 / переход / закрытие | Последний снимок уже находится локально; очередь отправляется при загрузке следующей страницы приложения |
| Вход в Canvas | Профиль + один документ своего Space; без запроса всей коллекции видео |

Это не обещание отсутствия всех сетевых запросов. Авторизация, чтение при входе, API, загрузка файлов и сохранение результата используют сеть. Для нового Worker принадлежность к команде проверяется при создании сессии; подтверждение действует час и затем обновляется, без проверки Firestore на каждом polling-запросе.

Отправку HTTP-запроса в момент закрытия вкладки браузер не гарантирует. Поэтому F5 отправляет сохранённую очередь при следующей загрузке, а после закрытия без повторного входа изменения остаются только на этом компьютере. Для локальной копии нужны тот же браузерный профиль и адрес сайта. Не очищай данные сайта, пока есть несинхронизированные изменения. Между устройствами виден последний отправленный снимок. При одновременном редактировании одного Space на нескольких устройствах сохраняется последняя отправленная версия; совместного редактирования нет.

Снимок без истории undo ограничен 850 КБ перед отправкой в Firestore. При превышении лимита появится сообщение, а локальная копия сохранится. Если сеть или правила не позволили отправить результат, очередь повторит отправку при следующем входе. Повторная доставка не начисляет XP второй раз. После перезагрузки задачи продолжают проверяться по сохранённому `requestId`; ошибка сети не превращается в ошибку генерации.

## Spark: медиа и срок ссылок

- Готовое видео воспроизводится и скачивается прямо по URL BytePlus. Копирование в Firebase Storage и автоматическое скачивание MP4 отключены. В Firestore записываются владелец, запрос, параметры, стоимость при наличии, статус, XP, task ID и URL.
- Согласно BytePlus Retrieve a video generation task API, URL результата действителен 24 часа; для Dreamina Seedance 2.5 — до 100 скачиваний. Приложение показывает ориентировочный срок по времени получения результата. Позднее отчёты и XP сохраняются, воспроизведение старого видео не гарантируется. Ссылка не продлевается перезагрузкой страницы. Источник: https://docs.byteplus.com/en/docs/modelark/get-video-generation-task-api
- Изображения из Media остаются в IndexedDB на этом компьютере; при запуске их Base64 передаётся только провайдеру, никогда в Firestore или снимок Canvas. Один файл меньше 30 МБ; общий API запрос ограничен 60 МиБ. Параметры формата/размера изображения также проверяет модель.
- Видеореференсы Seedance требуют доступную HTTPS-ссылку. Добавить её можно кнопкой «По ссылке» в Media или настройках генерации. Локальное видео можно просматривать, но для отправки нужна ссылка. Автоматическая загрузка локальных видео в облако отсутствует. Источник: https://docs.byteplus.com/en/docs/modelark/create-video-generation-task-api
- При входе с другого компьютера схема нод доступна, локальные файлы требуется добавить заново. Аватар сохраняется только в текущем браузере.

## Формула Winners

`XP = round(10 × seconds / 4 × Q × (1 + 0.15 × (max(1, references) - 1)))`

`Q`: 480p → 1; 720p → 1.5; 1080p → 2. Для видео без референсов используется базовый множитель 1. Считаются только успешные результаты; ошибки образуют отдельный рейтинг.

| Параметры | XP |
| --- | ---: |
| 4 сек., 480p, 1 референс | 10 |
| 10 сек., 720p, 3 референса | 49 |
| 15 сек., 1080p, 5 референсов | 120 |
| 20 сек., 1080p, 10 референсов | 235 |
| 30 сек., 1080p, 15 референсов | 465 |

120 и 235 — исправления арифметики примеров из задания. Формула оставлена той, которую ты указал. У старых генераций может отсутствовать количество референсов или точная длительность; при пересчёте используется доступная запись и базовый множитель, без попытки угадать неизвестные параметры.

## Что предстоит включить в Firebase

Код подготовлен, но изменения ещё не действуют в удалённом проекте. Следующий этап можно пройти по скриншотам.

1. В `users/{твой UID из Authentication}` установить строковое поле `role: "superuser"`. Это единственный ручной bootstrap первого суперадмина. Email не используется как обход прав.
2. Опубликовать содержимое **firestore.rules** из этой версии. **storage.rules** — прежний файл для совместимости, в Spark не нужен. Вставлять обычный текст, без HTML-сущностей `&#x20;` и обратных слешей в конце строк.
3. Оставить тариф Spark. Firebase Storage не создавать и не включать.
4. После обновления страниц перезайти в приложение. Раздел Users появится у суперадмина; там можно создавать пользователей.
5. Если используется Worker, обновить и его код из папки `cloudflare-worker`, прежде чем выдавать доступ команде. Direct API режим также сохранён.
6. Для старых записей запустить «Пересчитать рейтинг» в Winners один раз. Это намеренная операция чтения истории, не фоновое действие Canvas.

`admin` больше не является действующей ролью; прежние такие профили нужно явно перевести в `superuser` либо `user`. Существующие Auth аккаунты без `users/{UID}` следует дополнить профилем, а не создавать повторно через форму нового пользователя.

## Файлы и запуск

Готовые страницы находятся в корне. Изменения в `source/` собираются командой:

```bash
python source/build.py
python -m http.server 8000
```

Открыть `http://localhost:8000`. Если команда `python` отсутствует, использовать `python3`. Не открывать `index.html` через `file://`: Firebase, IndexedDB и загрузки рассчитаны на HTTP(S).

При обновлении поверх старой папки удалить оставшийся `saved-values.html`. API credentials из старой версии переносятся в хранилище текущего UID только при совпадении с метаданными его подключения. Если старый ключ был сохранён только локально без метаданных владельца, его потребуется заново ввести в My settings. Ключи не записываются в Firestore.

Общий Worker URL можно указать в `source/firebase-config.js` → `apiGatewayUrl` и пересобрать HTML. Тогда участникам не нужно вводить этот публичный адрес отдельно. ARK API Key остаётся секретом Worker. В Direct режиме ключ и подключение отдельные для каждого пользователя в браузере.

## Курсоры

Векторные курсоры 32×32 в бело-синем стеклянном стиле предоставленного листа: обычная стрелка, наведение/нажатие, рука, grab/grabbing, ввод текста, связи/выделение, ожидание и недоступность. CSS встроен в HTML: дополнительные сетевые запросы не нужны. Отдельные SVG лежат в assets/cursors. Точка клика находится на кончике стрелки или пальца, а не в прозрачном углу. Состояния включаются по типу элемента и действиям Canvas. Работают в пределах приложения на устройствах с мышью; при неподдерживаемом формате используется системный курсор. Настройки курсора Windows не меняются.
