# Исправление BytePlus 404 — Magic 0.7.3

## Причина

При Direct mode модель берётся из `fields.model` ноды. Старые схемы могли хранить
`seedance-2.5`. Это значение перекрывало правильную модель в конфигурации.
Для ModelArk официальный ID: `dreamina-seedance-2-5-260628`.

В Worker модель выбирается отдельно через `BYTEPLUS_MODEL`. Его настройка не
влияет на Direct mode. Значение этой переменной в развёрнутом Worker здесь не проверялось.

## Что изменено

- `source/domain.js`: нормализация старых названий, сохранение явных model/endpoint ID.
- `source/canvas.js`: исправление модели при восстановлении нод, включая undo/redo.
- `source/app.js`: нормализация в записи генерации и в запросе к API; понятная ошибка 404.
- `source/pages.js`: проверка API-ключа больше не обещает доступ к модели.
- `cloudflare-worker/worker.js`: защита от старого значения `BYTEPLUS_MODEL`, согласованная `/health`.
- Все корневые HTML пересобраны. GitHub Pages использует именно эти HTML.

## Применение через VS Code

1. Скопируй содержимое папки `aiagr-main` в текущую папку проекта с заменой файлов.
   Сохрани существующую папку Git и свои локальные файлы.
2. Выполни `git add .`, затем `git commit -m "Fix BytePlus model ID"`, затем `git push`.
3. Дождись успешной публикации Pages и обнови сайт через Ctrl+F5.
4. Старые ноды не нужно удалять; граф, промпты и связи сохраняются.
5. В BytePlus → Activation management напротив Dreamina Seedance 2.5
   должен быть статус **Activated**. Если стоит **Not activated**, нажми **Activate**
   и заверши активацию в аккаунте, которому принадлежит твой API-ключ.

Для Direct mode менять Cloudflare не требуется. При использовании Worker
обнови его отдельно; GitHub Pages не развёртывает Worker. Если есть переменная
`BYTEPLUS_MODEL`, укажи `dreamina-seedance-2-5-260628`.

## Проверка

`node --test tests/domain.test.cjs tests/worker.test.mjs`

`npm run test:browser` (нужен установленный Chromium для Playwright).

Регрессионные тесты проверяют старую модель в графе и запросе, восстановление после
перезагрузки, Worker, ошибку 404 и сохранение отчётов. Провайдер и Firebase в
браузерном тесте заменены заглушками. Платная генерация не выполнялась.

Успешный GET списка задач подтверждает ключ и соединение, но не активацию Seedance.
Видео по-прежнему приходит по ссылке провайдера, без Firebase Storage и перехода на Blaze.
