# Magic 0.8.1 — Camera preview и удаление генераций

Полная версия поверх предоставленного архива 0.8.0. GitHub main проверен 7 октября 2026: `6c787327bb54c194a08ed560a9f69a20cedfb8dc`, совпадает с исходной базой архива. Сайт, Worker и живые правила Firebase в этом чате не публиковались; настоящие генерации и удаление существующих данных не выполнялись.

## Что изменено

- **Camera movement → Turn into video**: нода Camera теперь показывает видео выбранного пресета, название и полный промпт. Видео можно воспроизводить, останавливать и перематывать. Пример восстанавливается после F5 по cameraId; это работает и для уже добавленных нод 0.8.0. Он остаётся примером движения камеры; в запрос модели передаётся промпт пресета. Если сайт с примерами недоступен, появляется сообщение, промпт продолжает работать.
- **Assets**: у суперадмина появилась отдельная кнопка **Удалить из базы** для completed, failed и cancelled, включая чужие и архивные записи. Перед удалением приложение просит подтверждение. Запущенные задачи удалять нельзя. Обычный пользователь может архивировать своё, но не удалять результаты из базы.
- Удаление убирает документ `videos/{id}` целиком: промпт, ошибку, ссылку, подтверждение задачи и остальные параметры. Документ отсутствует в Assets, Dashboard и отчётах. Файл на стороне провайдера и сохранённая схема личного Canvas не удаляются. Накопленный lifetime-рейтинг не уменьшается; ручной пересчёт рейтинга учитывает только оставшиеся записи.
- В `videoDeletions/{id}` остаётся **только UID владельца**. Это служебная отметка, без промпта, ошибки, видео, URL или API-ключа. Она нужна, чтобы старая вкладка или очередь синхронизации не восстановила удалённый результат и не начислила XP повторно. Список этих отметок недоступен пользователям; чтение конкретной отметки доступно её владельцу и суперадмину. Изменять и удалять отметки из приложения нельзя.
- Сборка использует UTF-8 явно, чтобы исходники и русские тексты корректно собирались в Windows.

## Кто что видит

Суперадмин (`role: superuser`) запрашивает генерации всех пользователей в Assets и отчётах. Имя автора указано на каждой карточке; поиск ищет также по автору. Пользователь (`role: user`) запрашивает только записи со своим UID. Firestore запрещает чтение чужих результатов обычным пользователем. Spaces и исходные медиа остаются личными для всех, включая суперадмина.

Для воспроизведения чужих **OpenRouter**-генераций новые задачи должны создаваться через общий обновлённый Worker из архива 0.8.0. Один и тот же Worker URL нужно указать участникам и суперадмину. Ролики, созданные в Direct-режиме, автоматически не переходят в Worker. Подробная настройка: [UPDATE_0_8_RU.md](UPDATE_0_8_RU.md). Актуальные опубликованные правила и Worker отдельно не проверены.

## Установка

1. Сохрани копию существующего проекта. Скопируй содержимое папки `aiagr` из архива в локальную папку репозитория, сохранив существующую `.git`.
2. **Сначала обнови правила базы**: Firebase Console → проект **aiagr-80390** → **Firestore Database → Rules**. Замени текст содержимым `firestore.rules` из этого архива → **Publish**. Старые правила запрещают новое удаление и чтение служебных отметок. До обновления правил новый сайт публиковать не следует. Альтернатива из настроенного Firebase CLI: `firebase deploy --only firestore:rules --project aiagr-80390`.
3. Готовые HTML уже пересобраны. После дальнейших изменений запускай `python source/build.py`. В VS Code → Source Control проверь изменения, сделай commit и push обычным способом. Для Pages используется main/root, если эта настройка сохранена в репозитории.
4. Для командного воспроизведения OpenRouter обнови **весь** проект `cloudflare-worker` по инструкции 0.8.0. Сохрани имя существующего Worker и его подписывающий секрет.
5. Обнови сайт через Ctrl+F5. Проверь двумя аккаунтами: суперадмин видит обоих авторов, пользователь только себя; Spaces остаются личными. Добавь Camera movement и проверь видео внутри ноды после F5.
6. На тестовой Failed-карточке сначала отмени подтверждение удаления, затем подтверди. Проверь, что запись исчезла после обновления Assets и отсутствует в коллекции `videos`. Не удаляй служебную отметку вручную.

## Проверки в этом чате

- Сборка всех статических HTML прошла.
- 28 существующих модульных тестов прошли.
- 4 новых теста Assets прошли: запросы по ролям, удаление чужого результата суперадмином, запрет обычным пользователям/для активных задач, удаление Failed и защита от восстановления старой очередью.
- Добавлен тест реальных Firestore Rules для атомарного удаления и запрета повторного создания. Здесь он **не запускался**: зависимости Firebase и локальные эмуляторы отсутствуют.
- Расширен браузерный сценарий: воспроизведение пресета в ноде после F5, отмена/подтверждение удаления, роли. Здесь браузерный сценарий **не прошёл запуск**: среда блокирует создание процесса Chrome (`spawn EPERM`). Визуальная проверка новой ноды в браузере остаётся необходимой.
- Проверки Worker используют имитацию API; реальные платные запросы не выполнялись.

Команды полного набора проверок в обычном локальном окружении: `npm ci`, `npm test`, `npm run test:rules`, `npm run test:browser`. Для браузерных тестов требуется Chromium Playwright (`npx playwright install chromium`), для эмуляторов — Java. В ограниченном окружении Node тесты можно запускать по одному файлу с `--test --test-isolation=none`, чтобы тестовые заглушки API разных файлов не мешали друг другу.
