# Обновление 0.7.5: портреты BytePlus

Подготовлено на основе GitHub main `ec83c5e98912ede157362ddc4970d1d14983f913` от 6 октября 2026. Автоматическая отправка в GitHub не выполнена: подключённое приложение вернуло `403 Resource not accessible by integration` при создании ветки. Архив содержит полный проект, готовые HTML, исходники, Worker и инструкцию.

## Как обновить из VS Code

1. Сохрани отдельную копию своей текущей папки проекта, особенно если после указанного коммита в ней есть новые изменения.
2. Распакуй архив. Скопируй содержимое папки `aiagr` в свою существующую папку проекта, согласившись на замену файлов. Архив не содержит `.git`, `node_modules` и секретов Worker.
3. Открой папку своего проекта в VS Code и терминал: **Terminal → New Terminal**. Готовые HTML уже собраны, Python для этой замены не требуется.
4. Выполни:

```powershell
git status
git add .
git commit -m "Add verified BytePlus portrait assets"
git push origin main
```

Если удалённая ветка успела измениться или в твоей папке есть собственные правки, сначала сопоставь их в Source Control VS Code. Не используй force push. GitHub Pages обновится только если публикация уже настроена для main.

## Что нужно настроить после публикации

Одного push недостаточно для Assets API. Открой [PORTRAITS_RU.md](PORTRAITS_RU.md): потребуются права библиотеки BytePlus, AK/SK в Worker, callback и R2 binding для локальных фото. После настройки опубликуй новый Worker и подключи его URL в My settings. Firebase остаётся на Spark.

Основные новые файлы: `cloudflare-worker/ark-assets.js`, `cloudflare-worker/portraits.js`, `source/portraits.js`, `portrait-callback.html`. Также обновлены `worker.js`, `auth.js`, клиент API, Canvas, стили и собранные страницы.

Проверено: 20 автоматических тестов серверной части/логики и два сценария браузерного тестирования — общий регресс приложения и процесс портретов. BytePlus в проверках заменён тестовыми ответами: реальные платные генерации и настройка внешних аккаунтов не выполнялись.

Реальный человек проходит собственную проверку. Следующие его фото регистрируются в той же группе, готовые Asset ID используются повторно. Фото с несколькими лицами не подходит для библиотеки реальных людей. Вымышленные AI-персонажи используют отдельные группы AIGC.
