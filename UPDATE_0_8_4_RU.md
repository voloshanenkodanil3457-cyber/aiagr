# Magic 0.8.4 — сохранение генераций обычных пользователей

В Firestore rules проверка существования новой записи videos была запрещена обычному пользователю. Приложение выполняет эту проверку внутри транзакции до сохранения видео и рейтинга, поэтому запись могла оставаться только локально. Разрешён get отсутствующей записи для зарегистрированного участника команды. Чтение существующих видео по-прежнему разрешено владельцу и суперадмину; список обычного пользователя ограничен его UID.

Assets повторяет отправку локальных завершённых генераций и восстанавливает отсутствующие записи из собственного Canvas, включая локальную копию. Сохраняется исходный generationId. Удалённые суперадмином результаты не возвращаются. Повторное открытие не начисляет рейтинг дважды. Новые снимки Canvas сохраняют полные метаданные результата. Для старого Canvas доступные параметры берутся из связанной ноды генерации.

Если сохранение отклонено, карточка явно сообщает, что результат находится только на компьютере. Срок жизни ссылки CDN не влияет на сохранение записи; восстановление записи не продлевает истёкшую ссылку провайдера.

## Обновление

1. Firebase Console → проект aiagr-80390 → Firestore Database → Rules. Замените правила полным содержимым firestore.rules из этого обновления и нажмите Publish. Это правила Firestore, не Storage.
2. На сайте обновите страницу через Ctrl+F5. Войдите под WebDorr в том браузере, где он генерировал видео, откройте Assets и нажмите «Обновить». Можно также восстановить данные из Canvas, ранее сохранённого в Firebase.
3. Войдите под Dan и обновите Assets: сохранённые записи команды видны суперадмину. Обычные пользователи видят только свои результаты.

Cloudflare Worker менять не нужно. Правила не публикуются автоматически при публикации GitHub Pages.
